# 창 이동 범위와 검색 포커스 UX 설계

## 1. 한 줄 목표

클립보드 기록을 빠르게 찾는 사용자가 창의 실제 빈 공간을 잡아 편하게 창을 옮기고, 앱을 다시 활성화한 직후 바로 검색을 이어갈 수 있게 한다.

## 2. 문제

- 근거: 설치본 0.2.4는 헤더만 `-webkit-app-region: drag`로 선언되어 검색·목록·하단의 빈 공간에서는 창을 옮길 수 없다.
- 근거: `BrowserWindow.focus()`는 네이티브 창만 활성화하며, 렌더러의 검색 입력 요소에 포커스를 보내지 않는다.

## 3. 사용자와 맥락

Windows 11에서 단축키로 copy-manager를 열어 이전 클립을 검색하는 개인 파워유저가 대상이다. 카드 클릭, 휠 스크롤, 설정 변경처럼 기존의 직접 조작은 창 이동보다 우선한다.

## 4. 사용자 여정

1. 사용자가 단축키·Alt+Tab·작업표시줄로 앱을 활성화한다.
2. 모달이나 우클릭 메뉴가 없으면 기존 검색어는 유지한 채 검색 입력창이 포커스를 받는다.
3. 사용자는 입력을 이어가거나 실제 빈 공간을 드래그해 창 위치를 바꾼다.
4. 드래그가 끝난 후 저장된 좌표는 다음 실행에서도 복원된다.

이번에 해결하는 단일 차단점은 좁은 헤더 외에는 창을 이동할 수 없고, 재활성화 뒤 즉시 검색을 이어갈 수 없는 점이다.

## 5. 핵심 흐름과 예외

- 빈 본문과 하단 안내 영역은 드래그할 수 있다.
- 카드 목록·스크롤바·검색·탭·헤더 버튼·토스트·리모컨은 해당 기능을 조작하며 창 이동을 시작하지 않는다.
- 설정/상세/확인/알림 모달 또는 우클릭 메뉴가 열려 있으면 현재 조작 대상의 포커스를 보존한다.
- 드래그 좌표 저장 실패는 창 이동을 막지 않으며 콘솔 경고만 남긴다.

## 6. 화면 / 출력 의도

- 기본 화면: 입력 가능한 검색창과 실제 빈 여백이 공존한다. 검색은 입력 우선, 빈 여백은 이동 우선이다.
- 모달/메뉴 상태: 해당 조작의 포커스를 유지하고 검색창으로 강제 전환하지 않는다.

## 7. 우선순위

### 하지 않음

- 카드나 스크롤 가능한 목록 전체를 드래그 영역으로 만들지 않는다. 클릭·스크롤과 충돌하기 때문이다.
- 검색어를 활성화할 때 지우거나, 창 위치를 새 설정 키로 중복 저장하지 않는다. 현재 값과 저장 경로를 유지한다.
- macOS/Linux별 창 동작을 추가하지 않는다. 이 앱은 Windows 전용이다.

- 안 하는 것(2개): 카드·스크롤 목록의 드래그화, 활성화 시 검색어 초기화.

### 이번에 함

- 상호작용하지 않는 빈 영역을 추가 드래그 영역으로 지정한다.
- BrowserWindow의 `focus` 이벤트를 렌더러에 전달하고, 안전한 상태에서만 검색창 포커스를 복원한다.

## 8. 성공 지표

- 카드 없는 본문 여백과 하단 안내 영역을 드래그하면 창이 이동하고, 앱 재실행 후 같은 위치로 복원된다.
- 단축키·Alt+Tab·작업표시줄로 기본 화면을 활성화하면 기존 검색어를 보존한 채 바로 입력할 수 있다.
- 모달/우클릭 메뉴가 열린 상태에서 활성화해도 해당 조작의 포커스가 검색창으로 바뀌지 않는다.
- 카드 클릭·탭 전환·검색 입력·스크롤 리모컨의 기존 동작이 유지된다.

## 9. 검증 계획

- 자동: `npm run typecheck`, `npm test`, `npm run build`로 타입·기존 저장소·번들을 확인한다.
- 수동: 개발 실행에서 M44(빈 영역 드래그/좌표 복원)와 M45(활성화 시 검색 포커스/모달 예외)를 수행한다.
- Plan B: 일반 빈 본문을 드래그 영역으로 만들 수 없으면 빈 상태 메시지·하단 안내 영역만 유지해 상호작용 충돌 없이 제공한다.
- Plan C: BrowserWindow `focus` 이벤트가 초기 로딩보다 빨리 오면 렌더러의 `window.focus` 이벤트도 같은 안전 조건으로 처리한다.

## 기술 부록

- 소유 파일: `src/main/window.ts`는 창 포커스 알림, `src/renderer/index.html`은 드래그/제외 CSS, `src/renderer/src/main.ts`는 모달·메뉴 예외와 입력 포커스, `notes/MANUAL-SMOKE.md`는 수동 검증 절차다.
- IPC 표면은 변경하지 않는다. main에서 이미 보유한 `webContents.send()`로 일방 알림을 보낸다.
- 위치 저장은 기존 `move` 이벤트와 250ms 디바운스를 재사용한다. Electron은 수동 이동 시 `move` 이벤트를 발생시킨다.
