# MANUAL-SMOKE — copy-manager S1/S2 수동 검증 절차

> Electron 창·전역 핫키·blur 동작은 **실제 디스플레이가 있어야** 검증 가능하다(헤드리스 불가).
> 아래 항목은 자동 검증에서 제외되며, 사용자가 직접 실행해 ✅/❌ 를 채운다.
> 자동 검증(설치·tsc·build·store 테스트)은 최종 보고 표 참조.

## 사전 준비
```powershell
cd C:\ai\projects\copy-manager
npm install      # 최초 1회
npm run dev      # electron-vite dev (HMR) — 또는 npm run build && npm start
```

## 기동 확인 (2026-06-28)
- `npm run dev` → main/preload/renderer 빌드 + **Electron 프로세스 기동까지 무에러 확인**(18초 폴링).
- ⚠ **창은 `show:false`로 시작** → 기동 직후 화면에 보이지 않음. **Ctrl+Alt+V로 띄울 것**(아래 M3). 이것이 win+v 대체 설계(핫키 호출형).

### 트러블슈팅 (기동 실패 시)
- `Error: Electron uninstall` / `Electron failed to install correctly`:
  - (1) Electron 바이너리 미설치 → `node node_modules/electron/install.js` (약 232MB 다운로드)
  - (2) main 번들에 electron 이 인라인된 경우 → `electron.vite.config.ts`의 `externalizeDepsPlugin()` + `external: ['electron']` 확인
- 포트 점유(`Port 5173 is in use`)는 이전 dev 잔류 프로세스 때문 — 자동으로 다음 포트 사용(동작 무관).

## 검증 항목 (보안 — 화면 캡처 방지, D28)

> ⚠ 헤드리스 불가 — 실제 캡처 도구로만 검증 가능. 기본값은 **켜짐(contentProtection=true)**.
> 동작 원리: Windows `SetWindowDisplayAffinity`. Win10 2004+ 는 캡처에서 **완전 제외**, 구버전은 **검은색**(WDA_MONITOR) 폴백.

| # | 절차 | 기대 결과 | 결과 |
|---|------|-----------|------|
| M25 | 캡처 방지 기본 동작 | Ctrl+Alt+V로 창 열기 → **Win+Shift+S**(영역 캡처)로 창 영역 캡처 → 캡처 결과에 창이 **안 보임/검은 영역**(다른 창은 정상 캡처됨) | ⬜ |
| M26 | 토글 해제 시 다시 보임 | 설정 ⚙ → **"화면 캡처 방지" 체크 해제** → 다시 Win+Shift+S 캡처 → 이번엔 창이 **정상적으로 캡처됨**. 다시 체크 → 또 안 잡힘 | ⬜ |
| M27 | 화면 공유/녹화 | OBS·줌/팀즈 화면 공유·Win+G 게임바 녹화 중 창 표시 → 공유/녹화 화면에 창이 **안 잡힘**(켜짐 상태). 해제하면 잡힘 | ⬜ |
| M28 | 영속/재시작 | 캡처 방지 해제 후 앱 재시작 → 해제 상태 유지(설정 영속). ☑ 재부팅 리셋이 켜져 있으면 재시작 시 기본값(켜짐)으로 복원 | ⬜ |

> 한계 명시: ① RDP·일부 가상화/원격 데스크톱 경로는 캡처 제외가 적용되지 않을 수 있음. ② OS·GPU 드라이버에 따라 폴백 동작(검은색)이 다를 수 있음. ③ 물리적 카메라 촬영은 방지 대상 아님(소프트웨어 캡처 한정).
